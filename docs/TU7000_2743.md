## Why the archive route does not apply

The sibling `samsung-tv-root` SDK archive route (not used here) requires all of:

- effective `cap_setgid,cap_sys_admin` on `/usr/bin/dotnet`;
- a .NET 3.1 or 6+ runtime;
- effective `cap_setuid,cap_setgid` on `/usr/sbin/sdbd-tarlauncher`;
- `tar --to-command`.

The TU7000 has no `/usr/bin/dotnet`. Its only .NET tree is
`/usr/share/dotnet`, which has framework directories only (no host binary) and
tops out at 3.0.0. The archive route therefore fails before staging. It was
not modified or relabelled for TU7000.

## Why the Remote PC/CIFS route applies

The TU7000 ships the same privileged CIFS chain reviewed by
[tiz0wn](https://github.com/sebastianspicker/tiz0wn/tree/main/research/remotepc-cifs-root):

- `ps_agent` runs as root from `/usr/apps/privileged-service/bin/ps_agent`;
- `mount.smb.sh` substitutes `username=`, `password=`, and `smbpath=` file
  contents into a `/bin/bash -c` command;
- `remotepc_rdp` exposes Shared Folder, and `remotepc_uilauncher` calls the
  privileged mount path.

The four reviewed artifacts are bit-identical to tiz0wn's Q60T 2743.0
anchors:

| Artifact | SHA-256 |
| --- | --- |
| `mount.smb.sh` | `37aaf2f05bf714332a6bf8f14b543ac9584a1b9a051341674a74fc0dd753c57e` |
| `ps_agent` | `402885bce04ca3a04c2cb322cbe83dd96d05e17457717b4627a85b0fdb004c33` |
| `remotepc_rdp` | `5d5b8277b20cae7ec993be7ff8f556a5f04cdff07109beb025c0e377f4dff9e4` |
| `remotepc_uilauncher` | `b87e23127fe04cfab9e2c43468a99a4c4aa0b852fd5923de17104c3cf9d872da` |

The shared `2743.0` number alone would not be enough; the hash match and the
live preflight are the evidence that binds the route to this model/build.

## Preflight

```console
uv run tizenpwn preflight "$TV_IP"
```

The command is read-only on the target. It requires:

- SDB `device` state and the package-name shell-injection timing probe;
- `UN65TU7000FXZA` from `sdb devices`;
- the exact tested build, kernel family, architecture, and Tizen prefix;
- `ps_agent`, `mount.smb.sh`, and Remote PC presence;
- all four reviewed artifact hashes.

A different model, build family, architecture, or artifact hash is rejected
before any lab or live trigger.

## Live one-shot UID-0 probe

This is not a read-only check. It starts a disposable RDP/SMB lab on the
host, prints one private Remote PC form card, and waits for two manual gates.
It saves a temporary Remote PC profile on the TV that must be deleted through
the TV UI afterward.

Prerequisites:

- `docker` and `openssl` on the host, and host TCP 3389/445 free;
- the TV and host on the same trusted LAN, with no relevant forwarding;
- the TV's Developer Mode host is this controller;
- the owner is at the TV with a pointer and can delete the saved profile.

Run:

```console
uv run tizenpwn cifs probe "$TV_IP" \
  --confirm TU7000-T-KTSU2AKUC-2743.0 \
  --accept-saved-profile
```

The lab performs these host checks before showing the form card:

1. builds a Docker image from `payloads/tu7000/cifs-lab` and verifies its
   content-hash label;
2. binds only the configured host address on 3389 and 445;
3. proves the RDP service answers a negotiation request;
4. proves the disposable PAM stack rejects a decoy password and accepts the
   exact one-shot password;
5. performs one disposable RDP login and one authenticated SMB share
   enumeration, and confirms the password is not in a process argument.

Then the operator:

1. opens Remote PC, chooses RDP, and enters the address, `owner`, the printed
   password, and the printed share name;
2. connects once, compares the printed RDP certificate fingerprint, and leaves
   persistent certificate trust unchecked;
3. waits for the disposable host xterm, types `CONNECTED`;
4. reveals the TV's in-session top toolbar, clicks Shared Folder exactly once,
   and types `CLICKED`.

The harness then:

1. requires exactly one new successful RDP login and exactly one new
   `NetrShareEnum Level: 1` event;
2. runs one two-push classifier for a fresh root-owned marker beginning
   `uid=0(root) gid=0(root)`;
3. reads the marker through SDB for the evidence record;
4. removes the marker and staging path, re-hashes the system files, checks
   `ps_agent`, stops and removes the lab containers, and verifies 3389/445 are
   closed.

A timeout, a repeated click, an extra SMB enumeration, or an ambiguous push
result is terminal. Do not retry the trigger in the same run.

### Cleanup after the probe

The host side is automatic. On the TV, exit Remote Access Player, delete the
saved temporary Remote PC profile, and revoke the disposable validation
device if one was paired. The profile and any pairing are TV-side UI state;
the harness does not automate or modify them.

## Authenticated one-shot agent

```console
uv run tizenpwn cifs command "$TV_IP" \
  --confirm TU7000-T-KTSU2AKUC-2743.0 \
  --accept-saved-profile \
  --command 'id' \
  --command 'uname -a'
```

The command reuses the same exact-target assessment, disposable lab, and two
manual gates. Instead of a marker, it stages a non-executable data file under
`/home/owner/share/tmp/sdk_tools`, and the Remote PC password carries:

```text
:;bash$IFS-c$IFS"$(cat$IFS/home/owner/share/tmp/sdk_tools/a<8 hex>)"
```

The mount helper's root `bash` reads that data through signed `cat` and passes
it to signed `bash -c` as inline code. The agent:

1. connects back to a host listener bound to the selected callback address and
   a fresh random port;
2. proves a 128-bit shared-secret challenge-response over the connection;
3. sends its fresh `id` identity;
4. runs the requested commands through `eval`, returning exit status and
   base64 output;
5. exits on an explicit `__EXIT__` from the host.

Directly executing the staged file is blocked by UEP on this firmware:

```text
[uep][bash] the file is NOT signed!!
```

The adapter does **not** change UEP or any UEP sysfs setting. It uses the
already-signed inline interpreter path, and the staged data is removed after
the run. The agent is one-shot per Shared Folder action; it installs no
persistent service or listener on the TV.

The host validates the same one-shot password in the disposable RDP/SMB lab,
so the exact string is accepted by PAM and SMB before the TV is touched.

## Result and limits

- Support is claimed only for `UN65TU7000FXZA` /
  `T-KTSU2AKUC-REL-202607021959`.
- The probe demonstrates one bounded UID-0 identity command. The authenticated
  agent demonstrates one bounded command batch per trigger. Neither changes
  UEP, installs a persistent service, or modifies firmware.
- The CIFS route is one-shot per manual Shared Folder action. There is no
  persistent root shell or background listener on the TV; every command batch
  requires a new reviewed trigger.
- The agent relies on the firmware's inline `bash -c` path because direct
  execution of the staged data is UEP-blocked. This is a policy boundary, not
  a UEP modification, and should be re-reviewed on any other build.
- The sibling `samsung-tv-root` `archive-root` QN90B/QN90F behavior is
  unchanged; this repository does not include that route.
