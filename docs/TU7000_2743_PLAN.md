# TU7000 T-KTSU2AKUC-2743.0 payload plan

> Historical note: this plan was written against the `samsung-tv-root`
> checkout. The TU7000 implementation now lives in this repository; paths such
> as `sdb.py`, `archive_root.py`, and `payloads/common*` refer to the original
> sibling project, not to `tizenpwn`.

## Outcome and completion

- Outcome: add a firmware-bound, on-demand payload for the owner's
  UN65TU7000FXZA running T-KTSU2AKUC-2743.0, using the current repository's
  transport and agent where compatible and tiz0wn's research where applicable.
- Completion: independently identify the target; demonstrate a fresh UID-0
  command result; execute a harmless command through the selected payload;
  verify shutdown, cleanup, and TV health; document exact supported artifacts.
- A diagnostic shell, a compiled payload, or an upstream success on another
  firmware family is not completion. Root-command proof and agent execution
  are separate milestones. Persistence and debloating are outside this plan.

## Requirements and choices

- Bind all live work to the exact model, firmware family, build fingerprint,
  and private device-identity digest. Keep identifying captures gitignored.
- Preserve existing QN90B/QN90F behavior and the user's existing Makefile edits.
  Do not relabel either model's exploit as a TU7000 payload or weaken its checks.
- Prefer an existing userspace route over developing a kernel/GPU exploit.
  Firmware flashing, boot changes, permanent services, and unsigned-execution
  protection changes are outside scope.
- Suggested boundaries: `sdb.py` for transport, `compatibility.py` for target
  assessment, `archive_root.py` for archive capability checks, `root_agent.py`
  and `payloads/common*` for an agent, and a separate TU7000 route if needed.
  Exact filenames and CLI shape can change after discovery.

### Discovery and sources

- Local baseline commit: `bcd6b2ce91d6b3e5bb99b7418b95c82662ac6653`.
- SDB reported UN65TU7000FXZA. The owner supplied T-KTSU2AKUC-2743.0.
  These have not yet been joined to a captured on-device build fingerprint.
- One preflight timed out after 15 seconds before shell confirmation. A later
  isolated check passed: connect 0.003s, device state 0.001s, shell timing
  probe 2.358s. The timeout's cause remains unknown. A callback capture has
  not yet been demonstrated on this target.
- The local archive route requires effective capabilities on dotnet and
  sdbd-tarlauncher, a supported .NET runtime (3.1 or 6+), and tar's
  `--to-command`. None is established on the TU7000.
- [tiz0wn](https://github.com/sebastianspicker/tiz0wn) studies a Q60T running
  T-NKLDEUC-2743.0, a different firmware family. Its shared numeric version
  does not imply compatibility with T-KTSU2AKUC.
- Its [Remote PC/CIFS notes](https://github.com/sebastianspicker/tiz0wn/tree/main/research/remotepc-cifs-root)
  report a bounded root-command proof, separate from an unvalidated live
  harness. Its [firmware analysis](https://github.com/sebastianspicker/tiz0wn/blob/main/docs/firmware-analysis.md)
  also records inconclusive Mali research; that is not a working fallback.

### Material unknowns and decisions

| Unknown | Least evidence needed | Decision |
| --- | --- | --- |
| Actual platform/runtime | Read-only build, architecture, identity, runtime and capability inventory | Choose matching build targets; never assume Q60T architecture |
| Callback reliability | Minimal identity command with explicit listener address and elapsed stages | Fix transport before debugging payloads |
| Archive route applicability | Existing route's prerequisites, then review of launcher behavior on matching artifacts | Prefer reuse if supported; otherwise classify as unavailable |
| CIFS route applicability | Exact TU7000 scripts/binaries and Remote PC feature presence | Continue only if source-to-sink behavior matches |
| Agent execution under firmware policy | Device-free executable or managed-runtime smoke test | Root identity alone does not prove an agent can launch |

## Steps

1. **Pin the inputs.** Record both repository commits and licenses; inspect
   repository guidance and relevant implementation/tests. Keep the upstream
   checkout separate. Record TU7000 artifact hashes instead of replacing
   tiz0wn's Q60T hashes or bypassing its target guards.

2. **Establish generic diagnostic access.** Use the confirmed SDB foothold for
   a minimal callback returning identity and exit status. Record connect,
   injection, accept, and read timings separately. If it fails, distinguish
   injection failure, staging failure, wrong route, and blocked inbound traffic.
   Do not increase global timeouts without identifying the failing stage.

3. **Capture the TU7000 baseline.** Collect build/kernel/architecture, SDK
   identity and security context, available runtimes, launcher capabilities,
   tar features, and Remote PC/CIFS component presence. Record TV health and
   hashes of files a proposed route could affect. Capture only relevant files;
   avoid credentials and unrelated user data.

4. **Choose a route from evidence.** Inspect the archive route's prerequisites
   and matching launcher implementation first. If unavailable, obtain the
   exact official TU7000 firmware or readable matching live artifacts and
   compare the Remote PC credential path with tiz0wn's analysis. Record
   provenance and hashes. Stop if neither route has supporting evidence;
   do not silently expand into novel kernel exploitation.

5. **Build the smallest offline proof.** For the selected route, reuse or adapt
   only the relevant host orchestration and payload. Exercise exact-target
   rejection, malformed/missing probe results, bounded execution, and cleanup
   through existing tests. For CIFS, reproduce the reviewed parsing behavior
   with TU7000 artifacts locally before live work. Port any needed upstream
   host assumptions to Linux; its documented local lab targets macOS.

6. **Demonstrate one bounded root command.** Prepare an exact-target runbook
   describing the trigger, expected fresh identity evidence, temporary state,
   and recovery. Validate a harmless identity command first, without launching
   an agent or changing system files. Classify absent, ambiguous, and successful
   results distinctly. A timeout is not permission to trigger again; inspect
   the resulting state and diagnose first.

7. **Adapt the reusable payload.** After root proof, test the actual runtime's
   device-free launch. Reuse the existing authenticated agent if compatible;
   otherwise implement the smallest runtime-compatible adapter. Verify an
   authenticated handshake, root identity, one harmless command, bounded
   disconnect behavior, and explicit shutdown. Keep acquisition separate from
   the command transport; document any required manual TV interaction.

8. **Integrate and document.** Add a TU7000-specific entry point and exact
   firmware assessment without weakening existing profiles. Package only
   required payload artifacts, preserve upstream notices, and document
   prerequisites, limitations, invocation, cleanup, and observed results.
   Do not redistribute Samsung firmware. Claim support only for the tested
   model/build; repeatability requires a separately reviewed fresh run.

## Verification

| Condition or risk | Hypothesis | Evidence and why sufficient | Rerun when | If it fails |
| --- | --- | --- | --- | --- |
| Correct target | Model and firmware match | Captured identity/build plus exact-match negative tests | Target or firmware changes | Reject before staging |
| SDK transport | Injection and callback work independently of root | Minimal identity/exit capture with stage timings | Network or transport changes | Diagnose failed stage |
| Viable acquisition | TU7000 has the selected route's prerequisites | Matching artifact review and focused offline tests | Route artifacts change | Choose the other evidenced route or stop |
| UID 0 | The fresh command executed on the TV as root | Fresh identity result with provenance and ownership checks where applicable | Acquisition changes | Classify failure; no blind retry |
| Usable payload | Firmware permits agent execution and commands | Launch smoke test, authenticated root handshake, harmless command | Runtime or agent changes | Separate launch-policy failure from acquisition |
| Cleanup and health | Temporary work ends without system modification | Baseline/post-run hashes, process/listener checks, TV health | Cleanup or lifecycle changes | Preserve evidence and diagnose residue |
| Existing routes preserved | Shared changes do not regress current users | Focused SDB, compatibility and affected archive/agent tests | Shared implementation changes | Fix regression before live work |

## Baseline, limits, and record

- No TU7000 root proof, callback proof, runtime inventory, or firmware binary
  comparison exists yet. Successful `make all` establishes host build success,
  not target compatibility.
- Retain commands, stage durations, repository revisions, artifact hashes,
  sanitized results, and initial failures. Keep private device data outside
  committed documentation.
- Rerun only checks affected by changed inputs. Expensive firmware extraction
  establishes route compatibility; a local service lab establishes transport
  behavior; neither substitutes for live identity evidence.
- Stop successfully when the exact target completes root acquisition,
  authenticated harmless command execution, shutdown, cleanup and health
  checks. Stop the selected route as unsupported or inconclusive when its
  prerequisites or root proof fail; report the missing evidence explicitly.
